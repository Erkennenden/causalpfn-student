# CausalFM ER V2：数据、模型和训练预算实验

V2 在你提供的 `causalfm_er_v1.zip` 上扩展 scaling 实验。该输入包内部已经是 CEPO 版本，并包含 8 卡主实验；这两部分沿用输入包的实现。

新增入口：`python -m scaling_v2`。它继续使用同一张保存的 N1000 ER 图、同一随机 f DGP，以及三个 CEPO 的 GMM NLL。模型输出 mu00、mu10、mu11，再计算 Direct、Spillover、Total；三种效应满足 Direct + Spillover = Total（浮点精度内）。

## 1. 先运行 20 步完整试跑

解压后进入 `causalfm_er_v2` 目录，在原来可运行 PyTorch/MUSA 的 Python 环境中执行：

```bash
python -m scaling_v2 smoke --device musa --output runs/v2_first_try
```

CPU 把 `musa` 改成 `cpu`；NVIDIA 使用 `cuda`。仍然使用完整的原 ER 图：训练任务 8 个、验证 2 个、测试 2 个、small 模型、batch=1、更新 20 步。此命令用于检查环境和全流程，不能据此判断预测精度或 scaling 定律。

查看 `runs/v2_first_try/status.json` 是否为 `complete`；效果与耗时在 `results.json`、`summary.csv`。`aggregate_summary.csv` 是跨种子统计表；这里只有一次训练，标准差留空。

## 2. V2 增加的实验范围

默认以 **medium、D=4096、8000 次更新**为公共参考配置，每次只改变一个因素：

| 比较方向 | 变化范围 | 固定条件 |
|---|---|---|
| 训练任务库大小 | 256、1024、4096、16384 | medium；8000 步 |
| 模型容量 | small、medium、large、xlarge | D=4096；8000 步 |
| 训练预算 | 2000、8000、16000 步 | medium；D=4096 |

| 模型 | Transformer 层数 × 宽度 | 当前 CEPO 实现的参数量 |
|---|---|---:|
| small | 2 × 32 | 41,280 |
| medium | 4 × 64 | 258,304 |
| large | 8 × 96 | 1,022,208 |
| xlarge（新增） | 12 × 128 | 2,602,496 |

共同参考配置只运行一次，因此是 **9 个配置 × 3 个训练种子 = 27 次训练**，共 222,000 次参数更新。默认 batch=4，验证任务 64 个、测试任务 128 个；种子是 2026、2027、2028。每次训练独立初始化，不复用上一配置训练出的权重。

这三组比较控制其余因素，不穷举所有组合。它们分别检查数据量、容量和训练预算的影响，尚不能直接回答全部因素的交互作用。

只预览计划，不生成任务或启动训练：

```bash
python -m scaling_v2 sweep --dry-run
```

运行完整默认实验：

```bash
python -m scaling_v2 sweep --device musa --output runs/scaling_v2
```

各任务库按 ID 嵌套；共同 `data_seed` 保证不同模型使用相同的数据。验证与测试使用独立流，并在配置之间保持一致。训练种子控制模型初始化和任务访问顺序；三个训练种子不等于三个独立抽样的数据集。

## 3. 小预算多种子检查

下面在原 N1000 图上运行 4 个配置 × 2 个种子，用来检查批量调度、统计和绘图，训练预算仍很小：

```bash
python -m scaling_v2 sweep --device musa \
  --task-counts 8 16 --model-sizes small medium --step-budgets 10 20 \
  --anchor-tasks 16 --anchor-model small --anchor-steps 20 \
  --seeds 2026 2027 --batch-size 1 --validation-tasks 2 --test-tasks 2 \
  --validation-every 10 --checkpoint-every 10 --output runs/v2_small_check
```

各轴的候选值必须包含自己的 anchor，且不能重复。想增加数据量或预算，只需修改 `--task-counts`、`--step-budgets`；模型档位使用 `--model-sizes`。修改学习率可传 `--learning-rate`，但不把不同学习率的结果混成同一个重复实验组。

## 4. 跨种子结果和曲线

```bash
python -m scaling_v2 report runs/scaling_v2 --plot
```

输出文件：

- `summary.csv`：每次运行、每种效应一行，包含 ITE RMSE/MAE、ATE RMSE/bias、参数量、预算和耗时。
- `aggregate_summary.csv`：每个可比配置、每种效应一行，输出 `*_mean` 和 `*_std`。
- `progress.json`：计划任务数、已完成任务数、尚未完成的运行目录。
- `v2_tasks_*.png`：任务库大小与误差。
- `v2_parameters_*.png`：模型参数量与误差。
- `v2_steps_*.png`：训练步数与误差。
- `v2_compute_*.png`：实测运行时间与误差。

标准差是**训练种子之间的样本标准差**，不是置信区间，也不代表重新抽取测试数据的波动。只有一个种子时不画误差条。相同配置下重复出现同一个 seed 的两个目录会报错，避免把复制的结果算成两次独立重复。

汇总按数据身份、训练设置、实际设备、CPU 线程数、模型配置和 PyTorch 版本分组。绘图还要求每个点的已完成种子集合相同；缺种子的配置会标为未完成重复实验。计划之外的目录不计入该计划统计。

`unique_train_tasks_seen` 是整个运行实际看过的任务数；`evaluated_unique_train_tasks_seen` 是最佳验证 checkpoint 之前实际看过的任务数。`steps` 是申请的总更新次数，`evaluated_step` 是实际用于测试的 checkpoint。图上出现 PARTIAL 表示部分 checkpoint 尚未见完任务库，或计划种子尚未全部完成。

时间包括任务加载/生成、训练、验证和测试；不包含 checkpoint/报告写盘等所有开销，也不是 FLOPs。首次生成缓存与读取已有缓存的时间不同；需要比较纯训练计算时看 `training_seconds_mean`。不同硬件或线程设置分开统计。

## 5. 续跑

保持同一套轴、种子和实验设置，原命令加 `--resume`：

```bash
python -m scaling_v2 sweep --device musa --output runs/scaling_v2 --resume
```

已完成的运行直接跳过；有 `model_last.pt` 的中断运行继续训练。若首次更新前就中断，可从校验通过的 `model_initial.pt` 恢复；若连初始 checkpoint 都未保存，使用新的输出目录重启。更改网格、数据 seed、学习率、batch 等实验设置时使用新目录；不会悄悄把两份计划混合。

继续一份未完成的运行时，实际设备、CPU 线程数和 PyTorch 版本必须保持一致，避免累计耗时混入两套运行环境。已完成的运行仍可跳过并保留原设备记录，新运行可以用另一设备，但会分组统计；换环境重新训练时使用新输出目录。即便这些标记一致，也应在同一台机器上比较耗时，设备编号不能完整识别硬件型号和后台负载。

单个配置可用 `train`；已有的本包 CEPO scaling checkpoint 可用 `evaluate`。初始的点效应 NLL 旧版本、8 卡主训练 checkpoint 与这个 scaling checkpoint 格式不同，不能混用。

## 6. 与原来 8 卡主实验的关系

V2 scaling 仍是**单进程、单卡、各配置顺序运行**，不通过 torchrun 启动。原来的 `launch_causalfm_docker.sh`、`run_causalfm.sh` 和 `causalfm_experiment` 保留，用于 40,960 任务、125 epochs 的 8 卡主实验及现有基线评估。这个 shell 入口不会自动运行 27 组 scaling。

你此前加入的 CEPO 标签、DR-Lasso 补丁、现有基线和 Docker 启动逻辑均保留。关于主实验的具体设置继续见 `README_CN.md`。在服务器容器内跑 scaling 时，进入解压后的项目目录使用本文命令。

## 7. 验证与修改位置

新增代码在 `scaling_v2/`，复用 `scaling_v1/runner.py` 的 CEPO 训练和测试逻辑，只新增 xlarge 容量档位。DGP、模型数学定义、CEPO 目标和效应公式保持与输入压缩包一致。

运行测试：`python -m pytest -q`。包内验证记录在 `audit/scaling_v2/`；文件校验可用 `sha256sum -c RELEASE_SHA256SUMS`。本地验证使用 CPU，MUSA/CUDA 真实硬件运行仍待服务器验证。默认 27 次正式实验没有代跑，试跑结果不作为精度或 scaling 结论。
